रोल-जागरूक पुनर्प्राप्ति इंजन - [रोल ओएस](https://github.com/mcp-tool-shop-org/role-os) के लिए एक संरचित ज्ञान आधार।

## यह क्या है।

एक ऐसा खोज इंजन जिसमें "रोल लॉ" (Role Law) यह निर्धारित करता है कि क्या जानकारी प्राप्त की जाएगी, उसका किस प्रकार से वर्गीकरण किया जाएगा, और उसका उल्लेख कैसे किया जाएगा। यह सामान्य "रेट्रीवल ऑगमेंटेड जनरेशन" (RAG) प्रणाली नहीं है, बल्कि इसमें इनपुट को सख्त नियमों के साथ नियंत्रित किया जाता है।

एक ही कार्य, अलग-अलग भूमिकाएँ, और भौतिक रूप से अलग-अलग साक्ष्य। यह 86 परीक्षणों के साथ 5 अलग-अलग भूमिकाओं में सिद्ध हुआ है।

## आर्किटेक्चर।

- **एक मानक डेटा संग्रह**, जिसमें मेटाडेटा, एम्बेडिंग और संस्करण जानकारी शामिल है।
- **भूमिका-आधारित नियंत्रण**, जो स्रोत नीति, शब्दावली, पुन: रैंकिंग और संश्लेषण को नियंत्रित करते हैं।
- **संरचित पुनर्प्राप्ति पैकेज**, जिसमें पूर्ण स्रोत जानकारी, अस्वीकृति के कारण और विश्वसनीयता का विवरण शामिल है।
- **बैकअप नियंत्रण प्रणाली**, जो खराब प्रदर्शन वाली स्थितियों (जैसे पुरानी, विरोधाभासी या कमजोर प्रमाण वाली स्थितियों) के लिए लागू होती है।

### पाइपलाइन।

```
task + overlay + corpus → query builder → BM25 + semantic → merge → metadata filter → rerank → bundle
```

### महत्वपूर्ण अनुबंध।

| अनुबंध। | विवरण। |
|----------|-------------|
| `RetrievalBundle` | प्रत्येक खोज प्रक्रिया के परिणाम को नियंत्रित करता है। |
| `RoleOverlay` | घोषणात्मक, भूमिका-आधारित डेटा पुनर्प्राप्ति कॉन्फ़िगरेशन। |
| `PacketKnowledge` | रोल ओएस पैकेट ज्ञान के संग्रह को कैसे ले जाते हैं। |
| `EvidenceProvenance` | सबूतों की उत्पत्ति और वे किस स्रोत से प्राप्त हुए, इसका पता कैसे लगाया जाता है। |
| `FallbackDecision` | क्षतिग्रस्त पुनर्प्राप्ति स्थितियों के लिए स्पष्ट शासन व्यवस्था। |

## स्थापित करें।

```bash
npm install @roleos/knowledge-core
```

**आवश्यकताएं:** Node.js >= 18। वैकल्पिक: [Ollama](https://ollama.com/) का उपयोग, जो `nomic-embed-text` के साथ सिमेंटिक खोज के लिए उपयोगी है।

## शुरुआत कैसे करें।

```typescript
import { CorpusStore, ingestFixtureCorpus, retrieve } from "@roleos/knowledge-core";

// 1. Create store and ingest corpus
const store = new CorpusStore(":memory:");
ingestFixtureCorpus(store, "./corpus.json");

// 2. Load a role overlay
const overlay = JSON.parse(readFileSync("./roles/security-reviewer.json", "utf-8"));

// 3. Retrieve with role governance
const bundle = await retrieve({
  store,
  roleId: "security-reviewer",
  taskText: "Review auth middleware for injection risks",
  overlay,
  lexicalOnly: true,
});

// bundle.selected — evidence chunks, scored and ranked
// bundle.rejected — why candidates were excluded
// bundle.provenance — trust and freshness posture
// bundle.warnings — degradation signals
```

## पायलट भूमिकाएं (पहला चरण)

| भूमिका। | पुनर्प्राप्ति प्रोफाइल। |
|------|------------------|
| उत्पाद रणनीतिकार। | उपयोगकर्ता मूल्य, समझौता, रणनीतिक मिसाल। |
| सुरक्षा समीक्षक। | खतरे के मॉडल, सीवीई (CVE), और शोषण के तरीके। |
| प्रतिस्पर्धा विश्लेषक। | बाजार संबंधी जानकारी, ईमानदार रूप से बताई गई कमियां, विकल्प। |
| दस्तावेज़ आर्किटेक्ट। | संरचनात्मक पैटर्न, नेविगेशन, सूचना का पदानुक्रम। |
| आलोचक/समीक्षक। | गुणवत्ता मानक, अस्वीकृति का पूर्व उदाहरण, अनुबंध का अनुपालन। |

## यह कैसे काम करता है।

1. **क्वेरी बिल्डर:** यह कार्य विवरण को अतिरिक्त शब्दावली (जैसे, महत्वपूर्ण वाक्यांश, पसंदीदा शब्द, समानार्थी शब्द) के साथ बढ़ाता है।
2. **लेक्सिकल खोज:** यह SQLite FTS5 के माध्यम से BM25 का उपयोग करके सटीक शब्द मिलान करता है।
3. **सिमेंटिक खोज:** यह ओलामा के माध्यम से एम्बेडिंग समानता का उपयोग करता है (यदि आवश्यक हो तो केवल लेक्सिकल खोज पर वापस आ सकता है)।
4. **मर्ज + डुप्लिकेट हटाना:** यह दोनों स्रोतों से संभावित परिणामों को मिलाकर डुप्लिकेट हटाता है।
5. **मेटाडेटा फ़िल्टर:** यह प्रतिबंधित स्रोतों, भूमिका-आधारित अपवर्जन, अप्रचलित परिणामों के लिए दंड, और विश्वसनीयता/दस्तावेज़ प्रकार के आधार पर प्राथमिकता निर्धारण लागू करता है।
6. **रोल रीरैंकर:** यह स्रोत विविधता को ध्यान में रखते हुए, पारदर्शी तरीके से भारित स्कोरिंग प्रदान करता है।
7. **बंडल असेंबली:** यह एक संरचित `RetrievalBundle` बनाता है, जिसमें पूरी ऑडिट ट्रेल (जांच का रिकॉर्ड) शामिल होती है।

## विश्वास और सुरक्षा।

यह पुस्तकालय केवल स्थानीय स्तर पर ही एक खोज इंजन के रूप में काम करता है।

- **जिन डेटा तक पहुंचा गया:** स्थानीय SQLite डेटाबेस, दस्तावेज़ के खंड, एम्बेडिंग।
- **जिन डेटा तक नहीं पहुंचा गया:** कोई भी उपयोगकर्ता क्रेडेंशियल, कोई भी व्यक्तिगत पहचान योग्य जानकारी (PII), कोई भी बाहरी एपीआई (सिवाय वैकल्पिक ओलामा लोकलहोस्ट के)।
- **कोई भी नेटवर्क से बाहर जाने वाला डेटा नहीं** सिवाय वैकल्पिक एम्बेडिंग जनरेशन के जो स्थानीय ओलामा के माध्यम से होता है (`localhost:11434`)।
- **कोई भी टेलीमेट्री डेटा एकत्र या भेजा नहीं जाता है।**
- **कोई भी गुप्त जानकारी का प्रबंधन नहीं किया जाता है** - यह क्रेडेंशियल्स को नहीं पढ़ता, संग्रहीत नहीं करता, और न ही प्रसारित करता है।
